# CH-188 — test plan

Documentation. There is no automated assertion that a runbook is followable, and
inventing one would be theatre — a test that greps for a path proves the string
is present, not that the procedure works.

## How it is actually checked

Patrick follows it. That is the only check that means anything here, and it is
the same check that caught the defect: the wrong path was invisible until
someone tried to use it.

The one mechanical guard worth having is that every path the runbook names
exists, or is explicitly a path the reader will create. That is what went wrong
— `C:\...\claude-env\runner\HarnessRunner` was neither.

## What would make this a false pass

Rewriting the `cd` to a different wrong path. The publish flow is what was
actually used to demonstrate AC7, so the runbook should describe that, not a
reconstruction of it from memory.
