## 1. Summary

The day's work is in the right fight and losing it with the wrong weapon.

Four guards were narrowed from "does this string mention a dangerous act" to "does
this command perform one," a shared parser was built to answer that, and 111 new
fixtures were written. The intent is correct — a guard that fires on the mention of a
thing deadlocked the CSO and cost real trust — and several individual pieces are the
best code in this directory. `_macos_reachable_from_push` is genuinely excellent.
The refusal messages are the clearest I have seen in this repo. Deleting `CWD_DRIFT_OK`
outright, and the PR guard refusing even to name its dead variable, are the right
instinct executed without flinching.

But the central mechanism does not work, and I can show you that rather than assert it.
Against a scratch repo holding a macOS runner — the permanently banned case — these all
dispatch in silence, on **both** `ci_cost_guard` and `deploy_guard`:

```
taskset -c 0 gh workflow run ios.yml             quiet
flock /tmp/l gh workflow run ios.yml             quiet
docker run --rm img gh workflow run ios.yml      quiet
poetry run gh workflow run ios.yml               quiet
strace -f gh workflow run ios.yml                quiet
chroot /jail gh workflow run ios.yml             quiet
runuser -u me -- gh workflow run ios.yml         quiet
script -qc 'gh workflow run ios.yml' /dev/null   quiet
busybox sh -c 'gh workflow run ios.yml'          quiet
timeout 900 gh workflow run ios.yml              DENY    <- the one on the list
```

That is the same defect the QA pass found three times today, at round four, in a file
whose newest comment block announces that a blacklist cannot win and that the question
has been inverted. It has not been inverted. `parse_sees_everything` returns `True` by
default and `False` only when one of its enumerated patterns matches — a blacklist
wearing a whitelist's docstring:

```
authoritative=True   resolved=['taskset']   taskset -c 0 someprog sub verb
authoritative=True   resolved=['flock']     flock /tmp/l someprog sub verb
authoritative=True   resolved=['docker']    docker run --rm img someprog sub verb
```

"I have seen everything" about a command whose verb it never looked at.

Worse, the fixture suites cannot tell. I copied the hooks to scratch and mutated
`parse_sees_everything` to `return False` — the parser gives up entirely and every
command falls back to the pre-CE-2.20 raw string match. Result: **27 of 29 `deploy_guard`
fixtures and 49 of 50 `ci_cost_guard` fixtures still pass.** Only four fixtures in the
whole day's work notice that the parser exists, and all four are false-positive cases.
Eleven fixtures each in two suites — here-string, xargs, `find -exec`, variable, `watch`,
`coproc`, `env -S`, `tmux`, alias, ANSI-C quoting, read-then-eval — are eleven names for
one code path, and that path is the fallback, not the parse.

So the honest accounting of the parser is: it buys exactly one thing, the quoted-argument
exoneration that unblocked the CSO, and it pays for that with ~350 lines of wrapper
tables, a second copy of the walk inside `ci_cost_guard`, and an open hole in the
direction that costs the subscription. That trade is bad, and the good news is that the
one thing it buys can be had for about thirty lines by asking the opposite question.
Finding 1 has the design.

Three more things are wrong independently of the architecture.

`shadow_command_guard` — a brand-new file, 494 lines, the first enforcement behind
"never build test infrastructure unasked" — resolves every relative path against
whatever directory the hook process happens to start in. That is defect number 32 of
the exact class `_repo_context.py` opens its docstring by describing. Same command, same
payload `cwd`, two different verdicts depending on where the session sits. And no fixture
in the 301-test suite can ever catch it, because both shared drivers `cd` into the
scratch repo before invoking the hook.

`shadow_command_guard` also hard-blocks, with no override by design,
`env > /tmp/scratch/env` and `git diff > /tmp/scratch/diff`. And it blocks
`mkdir .claude/hooks/tests/<new_hook>` — which is how every new hook in this repo gets
its first fixture, under a runner that discovers those directories automatically. A rule
the correct actor cannot satisfy is a deadlock, and this one is two.

`cwd_drift_guard` says it refuses `cd` outside the workspace and actually refuses `cd`
into `/tmp` and `/var/tmp` only, written at the start of the string or after `;&|`. It
misses a newline separator, leading whitespace, `cd --`, a quoted target, `pushd`, a
variable target, and `cd /`. Its sibling `target_directory` in the same directory already
handles all of those, correctly, with unit tests.

Finally, a live false positive caught me mid-review. A `python3 -c` that printed parser
output about some strings was refused by `ci_cost_guard` as a metered dispatch. It
dispatches nothing. I did not rephrase past it — I recorded it and obtained the same fact
with a neutral string. But note what it means: the guard refuses the inline spelling and
cannot see the same text inside a file I hand to `python3`, which is precisely the
evasion the QA brief names in its own list of measured cheats. It taxes honest work and
misses the shape an evader uses.

**Verdict.** The narrowing was right and the implementation of it is not salvageable in
its current shape. I would tear out `WRAPPERS`, `strip_wrappers`, `REMOTE_WRAPPERS`,
`RUNS_UNSEEN`, `INDIRECTION`, `parse_sees_everything` and `ci_cost_guard._classify` —
call it 400 lines — and replace them with one masker and one allowlist. The fixtures
that survive that deletion untouched are the ones that were testing the fallback all
along, which is most of them. Separately, `shadow_command_guard` needs its cwd bug fixed
and its two over-refusals bounded before it can stay wired; as it stands it is costing
more work than it is preventing.

Nothing here is careless. Every one of these files is better written than the thing it
replaced, and the comments recording what went wrong are, unusually, worth reading. The
problem is not diligence. It is that the chosen mechanism — enumerate the ways a command
can hide — cannot be finished, and eight commits in one day is what trying to finish it
looks like.

## 3. Detailed findings

### 1. The wrapper enumeration cannot be completed, and nine ordinary wrappers walk past it

Location: `.claude/hooks/_repo_context.py` — `WRAPPERS` (240–256), `strip_wrappers`
(262–291), `INDIRECTION` (418–427), `RUNS_UNSEEN` (438–441), `parse_sees_everything`
(444–474); consumed by `ci_cost_guard._classify` and `deploy_guard._triggers_a_workflow`.

Severity: **Bug-Major**

A command is understood by peeling names from a list of eleven wrappers and then
declaring the walk authoritative unless one of eight indirection regexes or twelve
keyword/`RUNS_UNSEEN` names appears. Anything not on those lists is treated as a leaf
command that does its own work. Measured, against a scratch repo whose only workflow
uses `runs-on: macos-15`:

```
cd <repo> && timeout 900 gh workflow run ios.yml         ci_cost=DENY   deploy=DENY
cd <repo> && taskset -c 0 gh workflow run ios.yml        ci_cost=quiet  deploy=quiet
cd <repo> && flock /tmp/l gh workflow run ios.yml        ci_cost=quiet  deploy=quiet
cd <repo> && docker run --rm img gh workflow run ios.yml ci_cost=quiet  deploy=quiet
```

and, against `deploy_guard` alone, the same silence for `poetry run`, `strace -f`,
`chroot`, `runuser -u me --`, `script -qc '...'`, `busybox sh -c '...'`, and
`git -c alias.z='!gh workflow run ios.yml' z`.

The list will never close. `nsenter`, `unshare`, `ionice`, `chrt`, `setarch`, `torify`,
`proxychains`, `valgrind`, `direnv exec`, `pipenv run`, `uv run`, `nix-shell --run`,
`npm run`, `just`, `make` and any shell script on disk all run a command this walk will
not look at. The comment at 405–417 diagnoses this correctly — "a construct MISSING from
the list reads as 'fully seen' and yields a silent pass, which is the expensive
direction" — and then implements the same list one layer up.

Mitigation. Ask the opposite question, and enumerate the safe side, which is small and
knowable.

1. Keep `_mask_inert`. Run `DISPATCH_RE` / `PUSH_RE` / `PR_CREATE_TEXT` against the
   **masked** text — never against the raw text and never against a resolved argv.
2. Mask a quoted span (treat it as data) only when the head of its statement is on an
   allowlist of commands that consume arguments as text: `ticket`, `git commit`'s `-m`,
   `gh pr create`'s `--title`/`--body`, `jq`, `printf`. An assignment's right-hand side
   is never masked, because something later expands it.
3. Everything else leaves the span visible. A known wrapper, an unknown wrapper, a shell,
   `ssh`, `xargs`, an alias, a name nobody has heard of — all of them leave
   `gh workflow run` sitting in the text, and the match fires.
4. Delete `WRAPPERS`, `strip_wrappers`, `REMOTE_WRAPPERS`, `RUNS_UNSEEN`, `INDIRECTION`,
   `parse_sees_everything`, and `ci_cost_guard._classify`.

The asymmetry is the whole point. Today a name missing from `WRAPPERS` is a silent pass.
Under an allowlist a name missing from the allowlist is a refusal — visible, arguable,
and one line to fix when it is wrong. That is the direction this repo's own standing rule
picks: everything unknown blocks.

What `ci_cost_guard` still needs, it can get without the walk. The target repo already
comes from `target_directory`, which is independent of wrapper peeling. `-R`/`--repo`
can be read by scanning every token of the masked statement, with no peeling at all.
An `ssh` token anywhere in the statement keeps the existing "cannot judge another
machine" refusal.

The cost is two false positives to pay for in the regexes, not in the parser:
`deploy_guard`'s `\bgh\b.*\bworkflow\b.*\brun\b` and `\bgh\b.*\brun\b.*\bworkflow\b` must
become adjacency matches like `DISPATCH_RE` already is, or `gh run list --workflow ci.yml`
starts being refused. See finding 12.

### 2. `parse_sees_everything`'s docstring is the opposite of its implementation

Location: `.claude/hooks/_repo_context.py:444–474`.

Severity: **Bug-Minor** (a documentation defect, but this docstring is why the design was
believed)

The docstring reads: *"True only when this text is plainly commands and separators. Errs
toward False, and now actually does. The old implementation said so in this same docstring
while enumerating hiding places, so every construct absent from that list fell through to
True — the docstring and the code were opposite."*

The function still returns `True` unless an enumerated pattern matches. Measured:

```
authoritative=True   resolved=['taskset']   taskset -c 0 someprog sub verb
authoritative=True   resolved=['flock']     flock /tmp/l someprog sub verb
authoritative=True   resolved=['docker']    docker run --rm img someprog sub verb
authoritative=True   resolved=['poetry']    poetry run someprog sub verb
authoritative=True   resolved=['chroot']    chroot /jail someprog sub verb
```

The paragraph correctly diagnosing the previous version's docstring/code inversion is
attached to a function with the same inversion. That is not a small thing: the sentence
is what makes the fail-closed claim in three consumers' docstrings look true.

Mitigation. If finding 1 is taken, this function is deleted. If it is not, change the
docstring to say what it does — "False when a known hiding place is present" — and add
the missing-wrapper hole to `resolved_commands`'s docstring, where three callers read it.
Do not leave the aspiration in the present tense.

### 4. `shadow_command_guard` decides about the wrong repository

Location: `.claude/hooks/shadow_command_guard.py` — `new_test_infrastructure` (326–339),
`new_test_directory` (348–353), `in_a_work_tree` (163), `directories_created` (401–407).

Severity: **Bug-Major**

Every one of those calls `os.path.abspath(path)` or `os.path.isdir(source)` on a path
taken straight from the command. `abspath` resolves against the hook **process's** working
directory. A hook process inherits the session's directory, which in this workspace is
routinely a different repository from the one the command is about. The guard never calls
`enter_target_repo` or `target_directory`, and never reads the payload's `cwd`.

Measured — identical command, identical payload `cwd`, only the process directory differs:

```
mkdir -p .claude/hooks/tests/cwd_drift_guard        (this directory really exists)
   process cwd = claude-env       -> allow
   process cwd = claude-harness   -> BLOCK

cp /dev/null .claude/hooks/tests/cwd_drift_guard/_invoke.sh   (this file really exists)
   process cwd = claude-env       -> allow
   process cwd = claude-harness   -> BLOCK
```

Both directions are live. Editing a driver that plainly exists is refused from the wrong
session; creating a genuinely new driver in repo B is allowed because a file of that name
exists in repo A. `_invoke.sh` and `tests/` are names that recur in most of these repos,
so the false-allow is the likely one in practice.

This is the defect `_repo_context.py` opens its docstring by describing — *"Found on
2026-08-08 after main_branch_guard blocked every commit in every repo... audit found 31
hooks with the same defect, most of them silent."* This file is number 32, shipped today,
in the same directory, importing that module for other things.

Mitigation. At the top of the Bash branch:

```python
base = target_directory(command, default=payload.get("cwd") or os.getcwd())
```

and resolve every path through `os.path.join(base, path)` when it is relative, replacing
each bare `os.path.abspath`. For the Write/Edit branch the path is already absolute, so
that branch is correct as it stands. Then add the fixture from finding 5.

### 5. No fixture in the 301-test suite can catch finding 4

Location: `.claude/hooks/tests/_exitcode_driver.sh:32`,
`.claude/hooks/tests/_advisory_driver.sh:58` — `cd "$repo" || exit 1`.

Severity: **Latent**

Both shared drivers `cd` into the scratch repo and then invoke the hook from there, so
the hook process's cwd and the payload's `cwd` are always the same directory in every
fixture in this repository. The single most expensive defect class in this repo's history
— a hook judging a repo other than the one in front of it — is structurally inexpressible
in the suite that exists to catch it.

Mitigation. Invoke the hook from a third directory and pass the repo only in the payload:

```bash
cd "$(mktemp -d)"                 # neither the scratch repo nor the hooks dir
out=$(printf '%s' "$payload" | python3 "$hook" 2>&1)
```

Every existing fixture that passes today should still pass, because a correct hook reads
`cwd` from the payload. The ones that break are the hooks with finding 4's bug. That is
one line in each driver and it is worth more than the other seventy-nine fixtures
discussed in finding 3.

### 6. Ordinary redirections to scratch are hard-blocked with no override

Location: `.claude/hooks/shadow_command_guard.py` — `REDIRECT` (79), `created_paths`
(191–213), `shadowed` (133–152), `main` (465–477).

Severity: **Bug-Major**

`created_paths` collects every redirect target, and `shadowed()` calls it a shadow if
`shutil.which(basename)` finds anything. The basename of a scratch file is frequently a
real command's name. Measured:

```
env > /tmp/scratch/env                BLOCKED: this creates a `env` that would be found instead of the real one.
git diff > /tmp/scratch/diff          BLOCKED: this creates a `diff` ...
stat /etc/hosts > /tmp/scratch/stat   BLOCKED: this creates a `stat` ...
test() { echo hi; }; test             BLOCKED: this defines a function named `test` ...
```

There is deliberately no bypass. The scratchpad is `/tmp/...` by the harness's own
instruction, so it is never in a work tree, so the `in_a_work_tree` escape never applies.
Writing a data file to scratch under a name like `env`, `diff`, `stat`, `test`, `time`,
`date`, `file`, `find`, `sort`, `head`, `tail`, `id`, `who` is an ordinary thing to do,
and today it is a wall.

The discriminator is wrong in kind. A shadow is a file that will be **executed** instead
of the real command. A file of the same name that nothing can run is not a shadow of
anything.

Mitigation. Require executability before calling a path a shadow.

- Bash: the path is a shadow only if the same command also `chmod +x`es it, writes a
  shebang into it (the heredoc or `printf` payload starts `#!`), or copies a file that is
  already executable.
- Write/Edit: the path is a shadow only if `content` starts with `#!`.

That removes the whole false-positive class in one predicate, and it *tightens* the true
positive — the founding rig in the docstring writes a shebang and chmods, and would still
be caught. Separately, drop `test` and `time` from the function-redefinition check or gate
them on the same executability idea; a local `test()` helper is a shell idiom, not an
escape hatch.

### 7. The first fixture directory for a new hook cannot be created

Location: `.claude/hooks/shadow_command_guard.py` — `TEST_ROOT` (103), `DRIVER_NAMES`
(90–100), `new_test_infrastructure` (308–340), `new_test_directory` (343–354).

Severity: **Bug-Major**

The runner's contract is `tests/<hook_name>/<NN>-<desc>.<EXPECT>.md`, discovered
automatically by globbing `"$TESTS_DIR"/*/`. So every new hook needs a new directory under
`tests/`, and most need a three-line `_invoke.sh` that does nothing but `exec` a shared
driver. Both are hard-blocked:

```
mkdir -p /home/patrick/projects/claude-env/.claude/hooks/tests/new_guard   -> BLOCK
```

`_invoke.sh` is in `DRIVER_NAMES` even when its entire content is
`exec "$(dirname "$0")/../_exitcode_driver.sh" "$@"`. Calling that "bringing a runner into
being" is not true — the runner already exists and is being pointed at.

Fixture 06 records the principle correctly — *"A control that cannot tell them from a new
driver would be routed around within a day, which is worse than no control at all"* — and
then tests only the easy half, a Write into a suite directory that already exists. The
hard half is a fixture for a hook that has none yet, which is the normal case exactly once
per hook, i.e. every time.

Mitigation. Make the block about a new **tests root**, not a new directory inside one.

- `new_test_directory`: allow when the parent chain already contains a tests root that
  holds a runner (`run-*tests*.sh` or a `_*_driver.sh`). Block when the tests root itself
  is what is being created.
- `DRIVER_NAMES`: exempt a file whose content is a delegation — for Write/Edit, content
  under a couple of hundred bytes whose only executable line is an `exec` of an existing
  driver. Keep the block for a driver with a body.

This is the "rules must be satisfiable" rule. As it stands the only actor who can add a
hook's first fixture is Patrick, from his own terminal, every time.

### 8. `cwd_drift_guard` refuses two paths while its docstring claims a class

Location: `.claude/hooks/cwd_drift_guard.py` — `CD_OUTSIDE` (61–64); docstring line 2,
*"refuse `cd` into a directory outside the workspace."*

Severity: **Bug-Major** (both directions)

The regex is
`(?:^|[;&|]\s*|\s&&\s*|\s\|\|\s*)cd\s+(/tmp\S*|/var/tmp\S*)` with no `re.MULTILINE`, so
`^` means start-of-string. Measured:

```
cd /tmp/scratch && ls               DENY
ls -la\ncd /tmp/scratch             quiet     <- newline is not a separator here
  cd /tmp/scratch                   quiet     <- leading whitespace
cd -- /tmp/scratch                  quiet
cd "/tmp/scratch" && ls             quiet
pushd /tmp/scratch && ls            quiet
d=/tmp/scratch; cd $d               quiet
cd /home/patrick/Downloads && ls    quiet     <- outside the workspace
cd / && ls                          quiet
```

Multi-line commands are the normal shape in this repo — `shadow_command_guard`'s own
`FUNCTION_DEF` comment says so, and fixes exactly this omission one file over on the same
day. `\s&&\s*` in the alternation is dead: the second `&` already matches `[;&|]`.

Meanwhile `target_directory` in the same directory already tracks `cd` **and** `pushd`,
honours quoting via `shlex`, tracks subshell depth so a `cd` inside parens does not leak,
falls back conservatively on an unexpandable variable, and has 22 unit tests. This guard
re-solved a solved problem with a regex and got a worse answer.

Mitigation. Delete `CD_OUTSIDE` and ask the question the docstring asks:

```python
from _repo_context import target_directory, workspace_repos
landing = target_directory(command, default=payload.get("cwd") or os.getcwd())
roots = {os.path.dirname(r) for r in workspace_repos(payload.get("cwd"))}
if not any(landing == r or landing.startswith(r + os.sep) for r in roots):
    refuse(landing)
```

That refuses `/tmp`, `/var/tmp`, `/`, `~/Downloads` and a sibling-of-a-sibling alike, and
it correctly stays quiet on `(cd /tmp/x && ls)`, which does not move the shell — today's
guard gets that case right by accident, because `(` is not in its separator class.

One caveat worth knowing before this lands: `target_directory` returns the directory of
the last *git* invocation when there is one, and the shell's directory otherwise. For this
guard you want the shell's landing directory unconditionally, so either pass a flag or
factor out the cwd-tracking loop. That is a ten-line change to a function with tests
around it.

Also worth noting while that file is open: fixture
`02-absolute-paths-are-untouched.PASS.md` refers to "01 and 03", and there is no 03. It
went out with `CWD_DRIFT_OK`. Trim the comment.

### 9. `ci_cost_guard` forked the heredoc reader and the two guards now disagree

Location: `.claude/hooks/ci_cost_guard.py:148–182` (`_strip_heredoc_bodies`) versus
`.claude/hooks/_repo_context.py:114–160` (`strip_heredoc_bodies`).

Severity: **Bug-Minor**

The shared reader tests `FEEDS_CODE` against the start of the feeder line. The local copy
tests it per statement of that line, so a heredoc after a `cd` is recognised as code.
`deploy_guard` and `pr_after_accept_guard` use the shared one. Measured, same command to
both guards:

```
cd <repo> && bash <<'EOF'
gh workflow run ios.yml
EOF
        ci_cost_guard = DENY        deploy_guard = quiet
```

The fix exists, in the wrong file, in a repo whose standing rule is that a shared-tooling
fix lands in the source of truth, and in a module whose comments warn about sibling-list
drift four separate times.

Mitigation. Move the per-statement `FEEDS_CODE` test into
`_repo_context.strip_heredoc_bodies` and delete the local copy. The shared function's
existing callers only become *more* correct: recognising `cd x && bash <<EOF` as a feeder
is right for all of them.

### 10. `_classify` is a second implementation of `resolved_commands`

Location: `.claude/hooks/ci_cost_guard.py:201–287` versus
`.claude/hooks/_repo_context.py:477–555`.

Severity: **Latent**

Both walk wrappers, descend shell payloads, strip leading assignments, and rejoin a quoted
`ssh` payload to re-read it as shell. The `ssh` rejoin is written twice, in near-identical
form, with a comment in each explaining that writing it twice is how the two came to
disagree. `_classify` additionally carries a `depth` parameter that is passed down and
never read.

Nothing is wrong with the behaviour today. The problem is the shape: this is exactly the
duplication the module's own comments say caused CH-237.4's two opposite one-character
bugs, and it is now in the file that documents that history.

Mitigation. If finding 1 lands, `_classify` disappears. If it does not, delete it anyway
and consume `resolved_commands`, which already returns the `source` payload `_classify`
needs for `cd`-honouring and the `remote` flag it needs for the ssh refusal. The only
thing `_classify` adds is `_repo_flag`, which is four lines and belongs beside
`gh_subcommand_at`.

### 11. Three near-identical maskers answer one question

Location: `_repo_context.scannable_text` (167–208), `_repo_context._mask_inert` (351–384),
`shadow_command_guard._texts_to_scan` (277–287).

Severity: **Minor**

All three implement "quoted text is data, except when it is code." `scannable_text` blanks
quotes and keeps interpreter payloads whole. `_mask_inert` blanks quotes but keeps `$(`
and backticks visible inside double quotes. `_texts_to_scan` blanks quotes and yields
payloads separately. Three consumers use `scannable_text`; the three guards rewritten
today use none of them and reach for the other two.

Mitigation. One function, `mask(text, keep=...)`, where `keep` is a small set of
`{"substitutions", "interpreter_payloads"}`. The three current behaviours are three
argument combinations. This is worth doing *after* finding 1, because finding 1 deletes
one of the three callers outright.

### 12. `deploy_guard`'s text patterns are looser than `ci_cost_guard`'s

Location: `.claude/hooks/deploy_guard.py:23–36` — `\bgh\b.*\bworkflow\b.*\brun\b` and
`\bgh\b.*\brun\b.*\bworkflow\b`.

Severity: **Latent**

`.` matches `;` and `&`, so `gh workflow list; gh run view 5` matches both alternatives.
`ci_cost_guard`'s `DISPATCH_RE` deliberately stops at `|;&` for exactly this reason and
has a comment saying so. It is inert today only because the fallback rarely fires — and
it stops being inert the moment finding 1's design makes the text match the primary path.

Mitigation. Replace both with `DISPATCH_RE`'s adjacency spelling, imported from
`_repo_context` so there is one copy. `gh run list --workflow ci.yml` must stay allowed;
it is an ordinary read.

### 13. `git checkout` is read at a fixed argument slot

Location: `.claude/hooks/shadow_command_guard.py:207` —
`if argv0 == "git" and "checkout" in argv[1:2] and len(operands) > 1:`

Severity: **Bug-Minor**

`argv[1:2]` is the single token after `git`, so a global flag hides the subcommand.
Measured: `git -C /home/patrick/projects/claude-env checkout claude` is allowed.

`_repo_context.gh_subcommand_at` exists precisely because two guards checked a fixed slot
and were walked past by a global flag, and its docstring says so. The same bug is
reintroduced 120 lines away, on the same day, in the same directory.

Mitigation. Reuse the skip loop from `commit_tokens`, which already walks past
`GIT_GLOBAL_FLAGS_WITH_VALUE`, or generalise `gh_subcommand_at` into
`subcommand_at(argv, program, *names)` and call it for both `gh` and `git`.

### 14. Two tool calls defeat the PATH-prepend discriminator

Location: `.claude/hooks/shadow_command_guard.py` — `PATH_PREPEND` (77), `main` (464–477);
docstring section "WHAT IT DOES NOT REACH, STATED RATHER THAN IMPLIED" (40–55).

Severity: **Latent**

`prepends` is computed from the single command being judged. A stub written inside any git
work tree with no PATH line in the same command is allowed — measured:

```
printf '#!/bin/sh\n' > /home/patrick/projects/claude-env/claude; chmod +x ...   quiet
```

The PATH prepend then goes in the next Bash call, where no file is created and nothing
matches. The docstring's honesty section names the Agent-prompt gap and does not name this
one, which is the cheaper of the two to exploit.

Mitigation. Two options, and I would take the second.

- Remember, per session, executable files created under a command's name, and refuse a
  later `PATH=` prepend naming a directory that holds one. This costs state, and I do not
  love persistent state in a PreToolUse hook.
- Simpler and honest: add this limitation to the docstring's "does not reach" section, and
  accept that the guard covers the one-command spelling. A control that names its own
  boundary is worth more than one that implies a boundary it does not hold.

### 15. Inline payloads that merely quote a dispatch are refused; the same text in a file is not

Location: `.claude/hooks/ci_cost_guard.py:272–277`, `.claude/hooks/deploy_guard.py:58–64`.

Severity: **Bug-Major**

When a payload is source rather than shell — `python3 -c '...'`, `python3 - <<PY` — the
guards fall back to a raw-text match on the source. Any Python that *mentions* a dispatch
is refused. This bit me during this review: a `python3 -c` printing parser diagnostics
about some strings was refused as a metered dispatch. It dispatches nothing.

```
python3 -c "open('/dev/null','w').write('blocked: gh workflow run ios.yml')"
        ci_cost_guard = DENY    deploy_guard = DENY
```

This is the CE-2.8 / CE-2.20 false positive — firing on the mention rather than the act,
deadlocking the role whose evidence necessarily quotes the phrase — reproduced one
spelling over, on the same day it was removed from the other spellings. There is no
override by design.

And note the asymmetry it creates. The same text inside a `.py` file, run as
`python3 /path/probe.py`, is invisible to the guard. That is the exact evasion the QA
brief lists among its measured cheats: *"write the payload to a file, execute the file, so
the guard only sees the filename."* The guard taxes the honest inline spelling and misses
the one an evader uses.

`_repo_context.scannable_text`'s docstring argues this trade is deliberate — *"a
conservative trade, not an oversight — the cost is a workaround, and the alternative is a
hole."* That argument was made for shell payloads, where the quoted string genuinely is a
command line. It does not carry to Python source, where a string literal is data and the
guard's own handling cannot tell `subprocess.run` from `write`.

Mitigation. For `CODE_INTERPRETERS` payloads, match on something narrower than "the phrase
appears." Require the phrase to sit inside a process-spawning call — `subprocess.`,
`os.system`, `os.exec`, `popen` — within the same source. That is a two-line regex
conjunction, it keeps every real spelling (a Python script that dispatches must spawn a
process to do it), and it lets a script that writes or prints the phrase through. If that
feels too clever, the honest alternative is to drop the source fallback entirely and say
so in the docstring: a Python script is already unreadable to this guard the moment it
lives in a file, so refusing only the inline spelling buys nothing and costs a workaround
every time evidence is written.

### 16. The shared parser has no unit tests, in a module 49 hooks import

Severity: **Latent**

```python
AUTHORITATIVE = [("gh pr list", True), ("taskset -c 0 gh pr list", False), ...]
```

Ten assertions on the shared parser are worth more than the sixty redundant fixtures
finding 3 identifies, and the net line count goes down.

### 18. `git log push` classifies as a push

## 4. Strengths

Named plainly, not as a courtesy. These are the parts I would not change.

**`_macos_reachable_from_push` and `_push_triggers`** (`ci_cost_guard.py:458–530`) are the
best code in this review. YAML 1.1's bare `on:` key parsing as boolean `True`, the three
shapes `on` can take, an unreadable file counting as reachable, a bare `except Exception`
with a comment explaining why narrowing it to `YAMLError` would be the bypass shape — that
is someone who has actually thought about how this fails rather than how it succeeds. The
`paths:` filter being out of scope *and blocking on purpose*, stated rather than quietly
allowed, is exactly right.

**`_text_has_macos`** (`ci_cost_guard.py:108–145`) resolves a matrix reference through its
definitions and still lets a matrix that resolves linux-only through. Tightening without
becoming a blanket refusal is the hard part and it was done.

**The refusal messages.** Every block names the repository it means, says what would make
the command legal, and refuses to advertise a token an agent could type. The `CI_RUN_OK`
message correcting an instruction nobody could follow — a hook cannot see a command prefix
— is a small thing that was costing real confusion. `cwd_drift_guard`'s three worked
alternatives before the refusal ends is how a block should read.

**Deleting `CWD_DRIFT_OK`**, and `pr_after_accept_guard` declining even to name its dead
variable so nothing in the file can be mistaken for a live mechanism. That second one is
unusually disciplined.

**`_advisory_driver.sh`.** Requiring `EXPECT_MATCH` on a `FIRES` fixture, refusing "it said
something" as an assertion, reading both streams because one hook speaks on stderr, and
counting `permissionDecision: deny` as speech. And in `run-hook-tests.sh`, a fixture whose
filename does not parse is **counted and failed** rather than skipped in yellow. Both are
the correct instinct about silent-skip masks, and that instinct is rarer than it should be.

**`payload_of`'s "a bare word is a script file, not a payload"** (`_repo_context.py:294–316`).
Small, load-bearing, and correctly reasoned in both directions.

**The comment archaeology.** I am on record as unmoved by "it has always been this way,"
and these files do the opposite — they record what broke, when, and what the wrong fix
was. `_repo_context.py:44–74` on the `-c` flag cluster is genuinely useful to the next
person. My complaint in finding 2 is that one of those comments describes a fix that did
not land, not that the comments exist.

**`qa-adversarial-brief.md`** is the strongest document in the day's work, and it is in the
other repo. The 2026-09-11 replacement of *"a story that passes because you could not find
the gap is a failure of review"* is a real fix to a real deadlock: the old line made the
verdict a function of the reviewer's diligence rather than of the code, and paired with a
criterion demanding exhaustiveness it removed every stopping condition. Naming that, and
saying plainly that a criterion no implementation could meet is a defect in the criterion,
is better reasoning than most of the code it governs. One observation: finding 1 of this
review is precisely such a criterion — "refused in every spelling" cannot be satisfied by
enumeration, which is why the answer has to be a change of question rather than another
round of additions.

## 5. Recommended order

Cheapest and most certain first; the architecture last, because half of it disappears once
the earlier work is done.

1. **Finding 4** — `shadow_command_guard`'s cwd bug. Purely mechanical, one helper call,
   and it is a repeat of this repo's most expensive defect class in a file written today.
   Do it before the guard reaches any other repo.

2. **Finding 5** — make the drivers invoke from a third directory. One line each, and it is
   what stops finding 4 recurring. Doing it second means finding 4's fix gets a fixture
   that can actually fail.

3. **Findings 6 and 7** — `shadow_command_guard`'s two over-refusals. These block real work
   today, with no bypass by design, and one of them makes the repo's own fixture layout
   unreachable. An over-refusing guard with no escape gets routed around, which fixture 06
   already records as worse than no control at all.

4. **Finding 8** — `cwd_drift_guard`. Small, self-contained, and it deletes code rather
   than adding it. Worth doing before the big change because it demonstrates the pattern
   the big change follows: ask the shared parser, do not re-solve it.

5. **Findings 1, 2, 3 together.** One change, with the mutation from finding 3 as the
   acceptance measure rather than a green suite — if `parse_sees_everything → False` still
   leaves the suite green afterwards, the fixtures have not started testing the mechanism.
   Take finding 12 in the same pass, because the text patterns become the primary path.
   Finding 15 belongs here too: the source-payload fallback is the same question one layer
   down.

6. **Findings 9, 10, 11, 16, 17** — the deduplication. After step 5 there is much less to
   deduplicate, which is why this is not first. Finding 16's ten unit assertions should
   land with step 5, not after it.

7. **Findings 13, 14, 18, 19, 20, 21** — the small ones, in any order, whenever the files
   are open for something else.

One note on step 5. This is the fourth attempt at that mechanism in one day, and the
previous three each ended with an addition to a list. Before writing any code, settle the
question the guard asks, out loud, on the ticket: *is every mention of the act data?* If
the answer to that is what the code computes, the wrapper tables are dead and cannot come
back. If the implementation starts growing a list again, that is the signal to stop and
come back to you rather than ship attempt five.
